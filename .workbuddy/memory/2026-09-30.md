## 限时作答完整实现（前后端，已修）

核心：把"限时"从前端倒计时变成服务端强制。

后端 `ExamRecordServiceImpl`：
- 常量 `SUBMIT_GRACE_SECONDS = 60`：提交宽限，容忍网络延迟与前端自动交卷时序误差
- 新增 `computeDeadline(exam, startAt, now)`：个人作答截止 = `min(exam.endTime, startAt + duration分钟)`
- `startExam`：新增"考试尚未开始"校验（原只有 endTime 校验）；抛 `IllegalArgumentException` 替代 `RuntimeException`
- `submitExam`：校验 exam 存在 → record 存在（必须先开考）→ `status != 2`（禁止重复提交覆盖成绩）→ `now <= deadline + 60s`，否则拒收
- `getExamRecordStatus` 扩展返回：`serverTime`（服务端毫秒时间戳）、`deadline`、`remainSeconds`（服务端权威剩余秒数）

`GlobalExceptionHandler` 新增 `IllegalArgumentException` → HTTP 400 + `Result.error(400, msg)`，
必须放在 `RuntimeException` handler 之前才不会被 500 兜住（此处 Spring 按精确度匹配，实际顺序无关，但保留注释）

前端 `views/student/ExamDetail.vue`：
- `serverTimeOffset = serverTime - Date.now()` 校准本地时钟
- 倒计时用服务端 `remainSeconds` 初始化（原来用本地 `now - startTime`）
- 每 30 秒 `syncRemainFromServer()` 校准一次，防止改系统时间延长作答
- 提交被 400/403 拒收 → 转只读 + 1.5s 后退回列表（拦截器已弹具体原因）
- 加载数据遇 400（未开考/已结束）也直接退回列表

## 头像 404 的真正原因（通用排查要点，务必记住）

报错 `NoResourceFoundException: No static resource avatars/xxx.png`，但文件明明存在。

原因：`addResourceHandler("/uploads/**")` 会把 URL 里 `/uploads/` 之后的部分当作相对路径。
访问 `/uploads/avatars/admin01.png` 时相对路径是 `avatars/admin01.png`，
而 location 配的是 `.../uploads/avatars`，于是拼成 `.../uploads/avatars/avatars/admin01.png`，多一层。

**修法**：handler 改为 `/uploads/avatars/**`，location 保持 `.../uploads/avatars/`，
这样相对路径就是 `admin01.png`，正好命中。
判断口诀：location 目录 + URL 去掉 handler 前缀 = 文件真实路径。

## 自动存卷改造方案（待用户确认，尚未实施）

现状：仅 `localStorage`，key = `exam_{userId}_{examId}_answers`，在 `selectOption` 和填空 `@input` 时整份覆盖写入；
30 秒心跳 `syncRemainFromServer` 只同步倒计时，不传答案。换设备/清缓存即丢。

调研发现的两个既有隐患（与是否做草稿无关，都该修）：
1. `ExamRecordServiceImpl.submitExam` 用 `answerRecordService.save(ar)` 逐题**插入**，
   `answer_record` 上 (exam_record_id, question_id) **没有唯一索引**。目前仅靠 status==2 门禁挡住重复提交，
   一旦引入草稿功能就会产生重复行。
2. `ExamRecordMapper.selectRecordsWithUserByExamIdPage`（教师批阅列表）**未过滤 status=2**，
   进行中的记录也会出现在批阅列表；`submitted_count` 统计口径同样把 status=1 计入"已提交"。

推荐方案（服务端草稿 + 复用心跳）要点：新增草稿上报接口 → 后端校验（归属/status=1/未超时）
→ 按 (record_id, question_id) upsert → `getExamRecordStatus` 回带草稿答案 → 前端加载时服务端优先、本地兜底
→ 交卷时草稿原地转正。`AnswerRecordService.batchSaveAnswers` 已存在但从未被调用。

## 自动存卷改造（已实施完成）

用户确认"按你认为最好的方法直接改，不用再问"，因此按 P0→P1→P2 全量落地。

改动清单：
1. **`smart_exam.sql`**：`answer_record` 增加 `UNIQUE INDEX uk_record_question (exam_record_id, question_id)`。
   新增 **`smart_exam_upgrade.sql`**：给已建库的环境做增量升级（含历史重复行清理 + ALTER）。
   现有种子数据经核查无重复，唯一索引可直接建成功。
2. **`ExamRecordServiceImpl`**：抽出私有方法 `syncAnswerSnapshot(examRecordId, examId, answersJson)`
   作为"落答案"的唯一入口——一次查出已有行，按题号 upsert；本次未作答的题删除已有行；
   只写 `user_answer`，不碰 `score`/`comment`。`submitExam` 改为调它（原先逐题 `save()` 会写重复行）。
   新增 `saveDraft(userId, examId, answersJson)`：校验归属 + `status<2` + 未过 `deadline+60s`。
   `getExamRecordStatus` 增加 `withAnswers` 形参，为 true 时回带还原成前端格式的答案
   （单选→下标、多选→下标数组、判断→0/1、填空简答→原文）。
3. **`RecordController`**：新增 `POST /api/records/draft`（body `{examId, answers}`），
   `/status` 增加 `?withAnswers=` 查询参数；`SecurityConfig` 把 draft 显式加进学生自助白名单。
4. **`ExamRecordMapper`**：批阅列表（分页版+非分页版）补 `AND er.status >= 2`；
   三处统计的 `submitted_count / graded_count / ungraded_count` 全部补 `status >= 2` 口径。
5. **前端**：`api/record.js` 加 `saveDraft`、`getExamStatus(examId, withAnswers)`；
   `ExamDetail.vue` 抽出 `formatAnswers()`（提交与草稿共用）、加 `draftDirty`/`draftSaving` 标记、
   `saveDraftToServer()`（失败静默、下轮重试）、挂到已有 30 秒心跳、切后台 `visibilitychange` 立即同步、
   加载时**本地优先**（本地为空才用服务端草稿回填）、头部显示"答案已自动保存 HH:mm:ss"。

关键设计决策：**恢复作答时本地优先**。因为每次改动都同步写本地，同一设备上本地必然最新；
只有换设备/清缓存（本地为空）才用服务端草稿。这样避开了"客户端时钟 vs 服务端 update_time 比较"的复杂度。
已知残留：A 设备答一半 → B 设备继续答 → 回 A 设备刷新，A 的旧本地会覆盖服务端较新的草稿。

验证：后端 `mvn clean compile` 通过，前端 `vite build` 通过。

## 补上"兜底自动交卷"（服务端定时任务）

用户提问"没有定时提交吗"后发现的洞：自动交卷原本只有前端三个触发点
（本地倒计时归零 / 心跳发现 `remainSeconds<=0` / 用户点退出），全都依赖浏览器开着。
学生关掉浏览器直接走人 → 卷子永远停在 `status=1`，既不会被批阅，
又因为上一轮给批阅列表加了 `status >= 2` 过滤而完全隐身。这个洞是上一轮改动放大的，必须补。

实现：
- `SmartExamApplication` 加 `@EnableScheduling`
- 新增 `task/ExamAutoSubmitTask`：`@Scheduled(initialDelay=15s, fixedDelay=60s)`，
  捕获异常避免调度线程退出
- `ExamRecordService.autoSubmitExpiredRecords()`：查 `status=1` 的记录，
  `startTime` 为空或 exam 不存在则跳过；`now > deadline + 60s` 才处理；
  **只翻 `status=2` 并写 `submit_time=deadline`，不重写答案**（草稿行已是最终答案）；
  单条失败 `LOGGER.warn` 不中断其余记录
- 项目原本没有任何 `@Scheduled`，也没有 `@Slf4j`（用显式 `LoggerFactory`），新类沿用显式 Logger 风格

注意：`exam.duration` 是 NOT NULL，所以不存在"duration 为空导致 deadline=startTime、一开考就被判超时"的风险。

## 防重复交卷（并发加固）

用户问"定时任务自动交了、用户也点了交卷，怎么避免重复"。查下来是 `check-then-act`，并发下挡不住。

补的四处：
1. `submitExam`：记录查询改 `.last("LIMIT 1 FOR UPDATE")`，与 `saveDraft` 互斥；
   并把 `status == 2` 放宽成 `>= 2`。FOR UPDATE 是当前读，后到的请求一定能看到 status=2。
2. `saveDraft`：同样加 `FOR UPDATE`。作用不是防重复，而是**错开 answer_record 的写入**——
   否则心跳草稿和提交会同时判断"这道题还没答案行"，都 INSERT，撞 `uk_record_question` 报错回滚。
3. `autoSubmitExpiredRecords`：`updateById` 改成条件更新 `WHERE id=? AND status=1`（CAS），
   否则会把用户真实的交卷时间覆盖成 deadline；另加"已有兄弟记录正式提交则跳过"，
   防止并发开考产生的孤儿记录被兜底交卷后，在教师端变成同一学生的第二份卷子。
4. 前端 `ExamDetail.vue`：新增 `submitting` ref 作为提交锁（连点 / 超时自动交卷撞手动交卷只放行第一个），
   按钮加 `:loading`；网络错误才解锁允许重试，400/403 不解锁（反正要跳走）。

顺手修的前端 bug：`@click="submitExam"` 会把 MouseEvent 作为第一个实参传进去，
`isAuto` 收到事件对象（truthy）→ `if (!isAuto)` 永远为假 → **提交确认框从来没弹过**。
改成 `@click="submitExam()"`。

已知残留：并发调用 `startExam`（双开页面同时进入）可能给同一考生插两条 exam_record。
没加唯一索引（会牺牲可重考性且需再改 schema），只在兜底交卷里跳过，孤儿记录会一直停在 status=1。

## 踩坑记录（通用）
删除 Java 方法时若用注释行做锚点，容易留下孤立的 `@Override`。
**一个重复的 `@Override` 会让 javac 在注解处理阶段直接失败，导致 Lombok 完全不执行**，
表现为几百个"找不到符号"（所有 getter 消失），极易误判为 Lombok/JDK 版本不兼容。
排查方法：看 `[ERROR]` 的第一条，通常就是根因；不要被后面的连锁错误带偏。
另外 `mvn compile` 是增量的，可能掩盖问题——验证时先 `mvn clean` 再编译。
